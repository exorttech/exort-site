# Exort Admin V2 — рабочая админ-панель

Рабочий маршрут: `/demo-admin`. Исходная страница: `pages/admin-v2.html`.

Открыть через работающий Live Server:
<http://127.0.0.1:5501/pages/admin-v2.html?restaurant=exort-demo>

Демо-вход: ресторан `exort-demo`, PIN `1234`. Для другого ресторана используется его идентификатор и действующий PIN. Доступ проверяет существующий сервер; параметр URL не предоставляет доступ сам по себе.

## Архитектура и файлы

- `pages/admin-v2.html` — независимая страница, вход, каркас приложения и доступные диалоги.
- `css/admin-v2.css` — отдельная дизайн-система и адаптивная компоновка.
- `js/admin-v2.js` — отдельная логика, API-клиент, представления, формы и графики.
- `tests/admin-v2.test.cjs` — изолированные контрактные тесты без сети.
- `docs/admin-v2-preview.md` — этот документ.
- `output/admin-v2-preview/admin-v2-overview-desktop.png`.
- `output/admin-v2-preview/admin-v2-menu-desktop.png`.
- `output/admin-v2-preview/admin-v2-editor-desktop.png`.
- `output/admin-v2-preview/admin-v2-analytics-desktop.png`.
- `output/admin-v2-preview/admin-v2-overview-mobile.png`.
- `output/admin-v2-preview/admin-v2-menu-mobile.png`.

Используется существующий стек HTML/CSS/JavaScript. Повторно подключены неизменённая утилита `js/admin-image-optimizer.js`, существующий логотип и фавикон. Генератор QR имеет ту же закреплённую версию `qrcodejs@1.0.0`, что и действующая админка.

## Карта реальных функций

| Сценарий | Существующий контракт |
| --- | --- |
| PIN-вход | `login` → `sessionToken`, ресторан, категории, блюда |
| Проверка сохранённой сессии и загрузка | `getData` |
| Добавление и редактирование блюда, фото, языки, цены, активность | `saveItem`, объект `item`; изображение передаётся в `imageData` после подготовки в браузере |
| Стоп-лист | `toggleStock`, `itemId`, `is_stoplisted` |
| Удаление блюда | `deleteItem`, `itemId` |
| Создание, переименование и видимость категории | `saveCategory` |
| Порядок категорий | `sortCategories` |
| Выделение блюд в новую категорию | `splitCategory`, `categoryId`, `category`, `itemIds` |
| Удаление категории | `deleteCategory`; режимы `empty`, `move`, `cascade` с явным подтверждением |
| Аналитика | `getAnalytics`, `range`, `sourceId`, `heatmapRange` |
| QR-источники | `getQrSources`, `createQrSource`, `deleteQrSource` |
| Wi-Fi QR | Локальная генерация; SSID и пароль не отправляются в API |
| Ресторан и настройки | Просмотр полей `restaurant`; API изменения реквизитов отсутствует |
| Выход | Удаление сессии выбранного ресторана из текущей вкладки |

С localhost запросы идут в существующий `https://exort.kz/api/exort-admin`. На домене используется `/api/exort-admin`. Секретных ключей во frontend нет. Ошибка 401 закрывает защищённое приложение. Данные из устаревших запросов другой сессии отбрасываются.

Обзор использует реальные количества, состояние меню и `updated_at` блюд. Аналитика использует серверные `summary`, `timeline`, `dayDetails`, `dishes`, `sources`, `insights`; собственные вымышленные значения и события не добавляются. Показатель «Вовлечённые гости» сохраняет серверную формулу `engagedRate` и отображается в процентах. Периоды: сегодня, 7 дней, 30 дней, всё время. Последний не имеет сравнения.

Редактор поддерживает RU/KZ/EN, как текущий редактор; дополнительные языки публичного меню не редактируются этим backend-контрактом. Автоперевод не представлен как гарантированная функция: серверный endpoint зависит от отдельно настроенного провайдера. Данные заведения доступны только для просмотра. Снятие доступа на сервере отдельным logout-контрактом не предусмотрено; выход очищает локальную сессию.

## Проверки

`node tests/admin-v2.test.cjs` и `node --check js/admin-v2.js` проходят.

Контрактные тесты проверяют привязку запросов к ресторану и сессии, экранирование текста, поиск и комбинирование фильтров, обязательные поля, числовые значения, поля сохранения и фотографии, сохранение черновика при ошибке, передачу выбранных блюд при разделении категории, стоп-лист и завершение просроченной сессии. Запросы в этих тестах перехватываются внутри Node; сеть и база не используются.

В браузере проверены реальный демо-вход, восстановление сессии при обновлении страницы, поиск с пустым результатом, фильтр стоп-листа, редактор, обязательные поля, переключение языков мышью и стрелками, предупреждение о несохранённых изменениях, подготовка изображения без сохранения, периоды и источник аналитики, QR-источники и форма создания, навигация на телефоне.

Обзор, меню и аналитика проверены на 375, 768, 1024, 1440 и 1920 px: общего горизонтального переполнения нет. На мобильном меню становится карточками, фильтры раскрываются отдельно, скрытая боковая навигация исключена из фокуса. Диалоги используют нативное управление фокусом; `alert()` и `confirm()` не используются. Предупреждение при закрытии вкладки использует стандартный `beforeunload`, поскольку браузеры не допускают собственный диалог в этом событии.

**Оговорка о демо-данных:** при браузерной проверке блюдо «Стейк рибай» было повторно сохранено с прежним содержимым через существующий API. Обновилась его дата сохранения. Категории, другие блюда и QR-источники при проверке не создавались и не удалялись; фото для предпросмотра не сохранялось. Полный цикл операций записи по живой базе не проводился, чтобы не изменять данные ресторана.

## Рабочая версия

Маршруты `_redirects`, `netlify.toml` и `functions/demo-admin.js` направляют `/demo-admin` на V2. Старая реализация и её отдельные CSS/JS удалены. Защищённая часть V2 отсоединена от DOM до успешного входа или проверки сохранённой сессии.

После завершения V2 по отдельному запросу пользователя из `index.html` и переводов `js/index.js` удалена фраза о минимальном сроке три месяца у тарифа 25 000 ₸. Эта правка главной страницы опубликована отдельно; файлы V2 в публикацию не включены.
